# UI/UX Engineering Guidelines

When the user gives you a plugin feature or an idea, do NOT generate standard, generic layouts. Automatically overhaul the interface using modern UI engineering principles.

## Aesthetic & Layout Standards
* **Visual Hierarchy:** Use strict sizing contrasts. Make key operational metrics prominent, and tuck secondary configurations into an expandable menu.
* **Component Styling:** Use premium interactive design patterns (e.g., modern dark mode surfaces, subtle inner-border shadows, 1px accent rings for active states).
* **Micro-interactions:** Add dynamic feedback like skeleton loaders, crisp hover states, and contextual tooltips.
* **Layout Structure:** Build clean, spacious card layouts instead of long vertical forms. Group parameters using CSS Grid or Flexbox auto-layouts.

## Execution Rules
1. **Analyze Strategy First:** Brainstorm 2-3 unique layout options in text/ASCII wireframes, explaining *why* they elevate the generic design.
2. **Build Mockup:** Output the standalone presentation code immediately (e.g., Tailwind CSS, React, or modern HTML/CSS) so it can be previewed in the terminal.
3. **Prevent AI Slop:** Do not use predictable generic templates. Use asymmetric layouts, distinct modern typography pairings, and clean spatial padding.
